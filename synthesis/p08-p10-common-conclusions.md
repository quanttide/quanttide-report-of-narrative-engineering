# p08-p10 三实验综合结论

## 核心发现链

```
p08: 母题缝隙分析    ──→  p09: 复刻作者审美    ──→  p10: 风格+母题合成
     ✅ 合格                    🟡 合格                      ✅ 合格
    "缺了什么母题"           "哪里风格不对"               "为什么不对 + 怎么改"
```

p05-p07 验证了母题能被提取、识别、约束生成。p08-p10 将这些基础能力转化为**编辑管线**：p08 诊断母题缺口并生成改进建议（Reflect），p09 用作者审美框架评审场景（Review），p10 交叉风格和母题两条管线，找到"风格弱点 → 母题根因 → 具体改法"的因果链。

---

## 六个跨实验共同结论

### 1. 风格和母题是互补编码——各有对方无法做到的事

| 能力 | 风格管线 (p09) | 母题管线 (p08) | 合成 (p10) |
|------|:---:|:---:|:---:|
| 诊断"哪里不对" | ✅ 11 维度评分 | ❌ 只知缺了什么，不知为什么重要 | ✅ 两者兼具 |
| 给出"怎么改" | ❌ "加强情感表达"（空洞） | ✅ 6 方向具体改法 | ✅ 最具体 + 最自然 |
| 保持审美一致性 | ✅ genre-specific 框架 | ❌ 不知风格边界 | ✅ 风格约束母题选择 |
| 量化作者个人品味 | ✅ confidence + tensions | ❌ 通用 motif pool | 🟡 映射可学习 |

**产品含义**：风格和母题不应是两套独立工具。评审报告不应以"情感表达 5/10 分"结束，而应自动触发"这个维度偏低 → 根因是缺了手势母题 → 试试在第三段加一个递毛巾的动作"。

### 2. "克制"和"反向"是从分析到编辑的质变

p08 的 6 方向框架中，增强/引入/借用/转化是从"母题缺口"自然推出的建议。但**克制和反向是两个本质不同的方向**：

| 方向 | 逻辑 | 产品含义 |
|------|------|---------|
| 增强/引入/借用/转化 | "缺 X → 加 X" | 标准编辑建议 |
| **克制** | "这个母题 weight ≤ 5，不加可能更好" | **不做某事的建议**——编辑智慧 |
| **反向** | "有意违抗这个母题，制造张力" | **创意建议**——超出"修复"的范畴 |

p08 中发现克制建议对低 weight 母题（歌声 weight=5）被评估为"高于引入"——这是数据支撑的产品设计决策：系统不应默认"每个缺的母题都要补"。

p10 进一步验证了这个逻辑：风格诊断可以提供"为什么克制是对的"（如"这个场景已有 2+ 高 weight 母题，再加会 overload"），而不仅仅依赖 weight 阈值。

**产品含义**：编辑工具的差异不在"能提多少建议"，而在"能提多少种不同类型的建议"——尤其是"不做"和"反着做"这两种反直觉的方向。

### 3. style.yaml 本身含有母题知识——两条管线不完全正交

p10 的关键发现：风格单层在 style_cover 上得分不低（14/20），且实验约束"不要提及母题名称"未能完全隔离母题知识。原因：

> style.yaml 情感表达 = "最高级的情感藏在细微处：递毛巾、整理书桌、旁听会议——爱意不在台词里，在行为里"

这段话同时是风格维度描述**和**母题操作手册。风格定义中天然嵌入了母题操作。

**产品含义**：
1. style.yaml 的维度描述越具体（含可操作元素），其作为编辑工具的效力越强——不需要等母题管线先跑
2. 但这也意味着 style.yaml 需要警惕"过度规定"——如果把所有母题操作都写进维度描述，就失去了母题管线独立发现的价值

### 4. 初稿 vs 成稿不是有效的跨场景基准

三个实验一致发现：LLM 的 1-10 风格评分在跨场景比较时不可靠。

| 实验 | 发现 |
|------|------|
| p08 | 成稿 D4（第十章 KTV）大面积缺失母题——但它是成稿，说明"母题覆盖"不一定是"好作品"的前提 |
| p09 | T2 初稿评分（均分 ~8.3）与 T1/T3 成稿（均分 ~7.7-8.0）无显著差异 |
| p10 | T3 成稿在"对话模式""时间结构"等多个维度上低于 T1 初稿 |

**产品含义**：
- 风格评审的 1-10 分数对**同一场景的迭代版本**做比较有意义，对**不同场景之间**做比较无意义
- 如果产品需要"写作进度"的量化指标，应使用场景内的相对变化（如"经过 3 轮修改后，情感表达从 5 升到 7"），而非跨场景的绝对分数
- 成稿的"好"不一定体现在风格维度得分上——可能体现在情节完整度、人物弧线等其他维度

### 5. 方法论收敛：pairwise blind + 两步诊断成为标准模式

p08-p10 的实验设计经历了显著的方法论进化：

| 实验 | 评估方式 | 诊断方式 | 问题 |
|------|---------|---------|------|
| p08 | 独立 1-5 评分 | 单步（给定缺失母题→LLM 归因） | 评分趋同（全 4-5 分） |
| p09 | 独立 1-10 评分 | — | 评分偏高一端（全 7-9 分） |
| p10 v1 | 独立 1-5 评分 | 单步（给缺失母题列表） | **全部得到相同分数 (4,3,3,4,4)** |
| **p10 v2** | **pairwise blind** | **两步（自由推断→匹配母题库）** | **产生了显著分化** |

**产品含义**：如果产品中的 AI 编辑建议需要用户选择"用哪条建议"，pairwise 比较模式（"A vs B 哪个更好"）比独立评分（"这条打几分"）更可靠。LLM 在相对判断上的表现远优于绝对判断。

### 6. 工具链已具备产品化的最小闭环

```
Review 阶段          Reflect 阶段                Rewrite 阶段
──────────          ────────────                ────────────
p09 风格评审        p08 母题缝隙分析            p07 母题约束生成
  ↓                    ↓                          ↑
  诊断"哪里不对"       诊断"缺了什么"               │
  ↓                    ↓                          │
  └──────→ p10 交叉诊断 ←──────┘                  │
              ↓                                    │
         风格弱点 → 母题根因 → 具体改法 ────────────┘
```

一个完整的用户流程：
1. 作者提交场景初稿
2. p09 做风格评审 → "情感表达维度偏低（5/10）"
3. p08 做母题缝隙分析 → "缺手势母题（weight=9）"
4. p10 交叉诊断 → "这两个有关联——加入递毛巾动作来修复"
5. p07 用母题约束生成新版本场景
6. p09 重新评审新版本 → "情感表达提升到 7/10"

**这个闭环已在实验层面验证，每个环节都有独立的实验数据支撑。**

## 三实验对创作者的意义

1. **不只是"AI 帮你改文章"，而是"理解你审美的 AI 帮你改文章"**——p09 证明 style.yaml 可以成为审美配置文件，p10 证明这个配置文件能让建议更具体、更自然

2. **建议有多重方向，不是每条都要听**——p08 的 6 方向框架让创作者可以选择"我想增强已有母题"还是"我想反着来制造意外"，而不是被动接受单一的"加 X 母题"建议

3. **母题和风格之间有一条可学习的映射**——p10 的风格-母题映射矩阵证明，LLM 可以自主发现"语言风格 ↔ 手势""时间结构 ↔ 十年"等关联。新作者加入平台后，系统可以通过分析其成稿自动建立他个人的"风格 ↔ 母题"对应关系

> 母题告诉你"怎么写"，风格告诉你"为什么这么写"。两者不是两套工具，是一个编辑的两只眼睛。
