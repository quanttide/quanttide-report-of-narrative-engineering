# p14 片段内部情节建议实验

验证能否将场景分解为"行为-反应"序列（双层动机+三值链状态），在此基础上诊断薄弱点，并生成多策略修改建议。

## 背景

p12 验证了 LLM 能诊断场景间的结构性薄弱点（因果跳跃/节奏失衡/动机不明），但粒度偏大。实际创作中作者更常遇到的问题是"这场戏内部哪里不对劲"——一个动作缺了前因、一句对话时机不对、一段情绪的转折太陡。p14 专注在这个粒度。

同时，p12 的诊断概念（因果跳跃、动机不明）虽然有效，但依赖人工判断。p14 尝试用"行为链标注→薄弱点诊断→建议生成"的三步流程将其结构化。

## 实验设计

| 项 | 内容 |
|----|------|
| 测试场景 | S1 咖啡厅重逢（高信息密度+核心约束最极致）、S2 酒吧表白（情感高潮+对话密度大） |
| 数据源 | story.yaml + motif.yaml + style.yaml（全量注入） |
| 模型 | DeepSeek Chat，temperature=0.2（链标注+诊断），temperature=0.3（建议生成） |

### 三步流程

**Step 1：行为链标注**。将场景分解为"行为-反应"序列，每个节点标注：
- `outward_motivation`：出行动机（给别人看的理由）
- `inward_motivation`：内隐动机（真实内心，可能未说出口）
- `tension`：两个动机是否有冲突
- `chain_status`：**完整**（因果链有支撑）| **有意断裂**（链断裂但这是设计张力）| **无意断裂**（链断裂且无合理支撑，是真薄弱点）

**Step 2：薄弱点诊断**。基于行为链识别 4 种类型：
- `causal_gap`：行为 A→行为 B 缺少逻辑过渡
- `motivation_blind`：人物做了某事，文本未提供动机支撑
- `emotional_jump`：情感状态变化跳过中间态
- `boundary_shift`：行为在"社交陌生人"/"心理熟人"边界上偏移

**Step 3：建议生成**。三种通用策略，不绑定 issue_type：
- **策略A** 加一个中间节拍：在行为前后插入停顿/动作/眼神
- **策略B** 注入感官动机：保留行为，用"看到/听到/想起"解释动机
- **策略C** 替代行为：换一种不同行为表达同样情感

### 关键改进（三次迭代）

| 迭代 | 问题 | 修复 |
|------|------|------|
| 初版 | S1 建议 LLM 将毛巾擦头发改为递毛巾（杀死核心母题） | 注入 motif.yaml + style.yaml 上下文让 LLM 理解"手势"母题 |
| 第一次修复 | S1 只有 fix_B 一条建议，没有选择空间 | 改为三策略通用（A/B/C 均不绑定 issue_type） |
| 第二次修复 | fix_B 动机基于"社交计算"而非"感官触发" | 强制动机必须来自"看到/听到/想起" |
| 第三次修复 | style.yaml 无边界规则，建议越界 | 重构 style.yaml，每个 dimension 增加 boundaries（含规则+判断标准） |
| 第四次修复 | 8.2 建议质量差（因果链断裂无人管） | story.tensions 增加结构层面描述 |
| 第五次修复 | S1 fix_C 安全化降级情感信号 | 约束策略C不得降级原行为的情感重量 |

## 结论

**行为链标注+薄弱点诊断的链路有效，但建议质量完全依赖底层数据的质量。** 链标注和诊断相对稳定（直接读 scene text 即可），建议生成则需要三个维度的数据注入才能稳定输出：

1. **style.yaml boundaries**：告诉 LLM 什么能做、什么不能做（预谋边界、认知边界）
2. **story.yaml tensions**：告诉 LLM 这场戏的结构难点在哪里（过渡缺失、因果链断裂）
3. **motif.yaml weight**：告诉 LLM 哪些元素是核心母题、不可轻动（手势、十年）

缺失任何一维，建议质量都显著下降。

### S1 三条可选建议（最终版）

| 策略 | 方案 | 核心思路 |
|------|------|---------|
| A | 低头看碰过她头发的手→眼神移到菜单→"焦糖玛奇朵？"（疑问） | 用停顿制造过渡 |
| B | 看到行李箱轮子上的泥水→"我帮你拉过去" | 用当下场景触发替代认知泄露 |
| C | 拉椅子让她坐下→问"你喝什么？"（保留她自选的空间） | 替代行为但不降级 |

## 产品意义

1. **p14 打通了从 YAML 数据到纵向建议的完整链路**：style.yaml（规则）+ motif.yaml（优先级）+ story.yaml（场次难点）→ p14 pipeline（诊断+建议）→ 提纲 md（面向写作者的执行摘要）

2. **三值链状态的区分能力是关键发现**：LLM 能区分"擦完缩回"（有意断裂=设计张力）和"直接点焦糖玛奇朵"（无意断裂=真缺失），这是 p15 提纲生成中"易错点"提取的基础

3. **boundaries 的建议质量提升比 motif 注入更显著**：style.yaml 重构（从正向描述改为规则+判断标准）对建议质量的提升，大于 motif.yaml 上下文注入的效果
